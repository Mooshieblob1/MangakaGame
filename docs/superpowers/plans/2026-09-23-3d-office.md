Deliver an actual usable office scene and its furniture management, extending
the existing simulation and Godot harness. Follow the design's proposed
defaults unless implementation evidence warrants a documented adjustment.
Preserve confirmed choices; a failed visual experiment is not permission to
replace accelerated timelapse movement with slow motion or a static diagram.

## Starting point and boundaries

- Sub-project 3 is already present in the working tree. Do not discard its
  uncommitted files or reimplement its finance/property/production systems.
- `MangakaSim` is engine-free .NET 8. Keep layout validity, ownership, capacity
  and financial transactions testable there without Godot.
- The existing Godot driver remains the only real-time clock. Office controls
  share `DebugMain` state, pause, save/load and command handling.
- Existing test counts in the prior delivery record are historical evidence,
  not a current run for this milestone. Establish a fresh baseline when build
  work starts; document pre-existing failures separately.
- No new package, external model service or asset marketplace is required by
  this plan. Any external asset needs an explicit license/provenance entry.
- Build in sequential slices. Each slice lists its own meaningful checks;
  broaden testing after integration, not after every material/label edit.

## 1. Establish baseline and prototype the riskiest visual

Inspect repository guidance and current changes. Run existing tests and the
warning-as-error build once. Confirm the installed Godot .NET renderer and
current smoke entry point; record results rather than copying old counts.

Create a small standalone test scene under `godot/Office/Prototype/`: a room,
occluding wall, workstation, simple articulated character and fixed camera.
Keep this independent of the live game state. Play the same walking/drawing
sequence at pause/1x/2x/4x/8x using the existing time-scale values.

Prototype pooled, depth-tested ghost silhouettes. Do not assume a built-in
whole-frame motion-blur option satisfies character-only timelapse. Add a
temporary intensity switch and capture short sequences at 1x and 8x.

Gate: the high-speed sequence really accelerates, walls/background/UI remain
sharp, trails stop/clear correctly, and the character is recognisable. Measure
the prototype with a repeated population before choosing the final trail
representation. Record the 1x walking/animation calibration against the
2.5-second hour. If the effect fails, fix the prototype before decorative work.

Likely files: `godot/Office/Prototype/*`, an initial
`godot/Office/TimelapseTrail.cs`, and `godot/Office/ASSETS.md`.
Use the existing renderer configuration unless a measured limitation requires
a documented change. Do not turn prototype controls into a second game clock.

## 2. Author floor plans and validate capacity in pure code

Add `src/MangakaSim/Office.cs` for stable definitions and DTOs,
`OfficeCatalog.cs` for furniture/template data, and
`Rules/OfficeLayoutRules.cs` for logical placement/access validation.
Names are implementation guidance, not a requirement to create giant files.

Define integer grid coordinates, quarter-turn orientation, footprints,
reserved chair areas, access/service anchors and fixed/shared/private zones.
Add explicit property-offer/template identity to new locations. Author one
family template, sixteen offer variations, and 2/4/8-seat employer areas.
Shared common areas are not tenant editing space or extra production capacity.

Use one occupancy/clearance model for validation and later visual navigation.
Implement whole-layout connectivity, footprint overlap and door/stock-zone
protection. Author a valid maximum-capacity baseline for every template.

Tests in `OfficeLayoutTests.cs`:

- All supported templates fit advertised workspaces and service/stock zones.
- Every rotation handles non-square furniture and access offsets correctly.
- A narrow connection, blocked door, enclosed chair, corner-only path or
  private-area shortcut is rejected even if object centres do not overlap.
- Fixed/common areas cannot be used to exceed the property's desk limit.
- Wall-decoration slots do not overlap doors/windows.

Gate: full capacity is demonstrated by logical layouts, not asserted from a
room's area. Adjust proposed dimensions within the stated bands where possible;
document any necessary band change as a game-layout decision.

## 3. Inventory, atomic editing and workplace capacity

Add `GameState.Office.cs`, typed office commands in the existing command
serialization registry, and office validation alongside the current save
validators. Furniture instances carry explicit owner/site, paid price,
placement/storage/sale status and stable IDs.

Implement preview/apply separation, revision checks, immutable copies of
caller collections, calculated prices, protected-cash checks, gross employer
budget consumption and resale receipt entries. Validate on a private candidate
state before committing any part of a batch. Do not debit or allocate live IDs
while dragging, previewing or searching.

Implement paired desk/chair capacity and automatic/manual desk assignment.
Update hiring and reservations, planning/production eligibility and staff
transfer checks to use the same workspace query. Include accepted future hires
and atomic occupied-desk swaps. Prevent an edit from stranding current staff.

Integrate modest chair/break/decor effects into existing wellbeing. Replace
the standalone numeric BreakRoom upgrade with an adapter that purchases and
places its two-seat furniture module. Keep property book storage independent.

Tests in `OfficeTransactionTests.cs` and focused existing studio fixtures:

- Rejected purchases leave the entire state, RNGs, IDs and log unchanged.
- Stale quotes, duplicate items, owner mismatch, repeated sales and a negative
  or forged price cannot mutate state.
- Sales can fund a valid batch while final cash reserves remain protected;
  they cannot recycle employer discretionary budget.
- Zero-paid/family/landlord assets cannot become a cash source.
- Empty branches can exist, but hiring/transfer requires complete workspaces.
- Preview/Cancel are pure; occupied-desk edits preserve unique reservations.
- Basic furniture preserves baseline production; benefit caps and break-place
  ordering work without any rendering, with no walking-distance multiplier.

## 4. Implement Auto-arrange as a bounded deterministic solver

Add `Rules/OfficeAutoArrange.cs`. Inputs are a template, inventory, required
staff/services, current layout and locks. Output is a proposed layout,
optional purchase suggestions, stored surplus and human-readable constraints.

Use authored patterns, desk banks and alternate orientations with stable
candidate ordering and lexicographic scoring from the design. Search by
candidate count, not timing-dependent random trials. Reuse the full validator;
never have separate relaxed rules for generated layouts.

Run searches on immutable snapshots. UI cancellation discards results; a
completed result whose revision is stale cannot be applied. Keep purchases
suggested until the player accepts the full cost preview.

Tests in `OfficeAutoArrangeTests.cs`:

- A seed/layout/inventory input returns the same output across repeated runs.
- Valid locks survive byte-for-byte; conflicting locks get an explanation.
- Staff workspaces take priority over optional decor; surplus is retained in
  storage, never silently deleted or sold.
- Existing eligible assets are reused before suggesting replacements.
- Every baseline template can furnish its required team within the bounded
  search, with inaccessible or unaffordable proposals never auto-applied.
- Search work is bounded on the 32-seat case; a failed fit is not reported as
  proof that no mathematical solution exists.

## 5. Integrate properties, careers and versioned saves

Extend `GameState.Properties.cs` and its operation validation. Use a typed
relocation payload containing the destination layout/purchases; the old Move
control must route through it rather than applying an unfurnished move first.
Preview combined lease, moving and furnishing costs. Preserve stock checks,
deposits, wage reserves and existing one-day downtime.

Keep family assets bound to one physical site across historical business
location records. Closures preserve business inventory in storage. Career
changes never transfer the old business's furniture merely because titles or
people follow. New employer areas have provided non-saleable baseline assets;
new own-business rentals must pay for desks or bring that business's inventory.
Include workspace/furniture requirements in follower acceptance and midnight
career revalidation. Former-business AI uses the same capacity and cash rules.

Bump required state to version 4 and use a new save filename. Implement
explicit supported version-3 import through a validator for the completed
Sub-project 3 schema. Materialise existing implicit facilities at zero paid
price, preserve all financial/title/stock state and gameplay RNGs, and map
legacy catalog/employer/home locations deterministically. Persist the imported
checkpoint; do not claim cross-version replay from an old NewGame seed.

Verify conversion on real-shaped completed-v3 fixtures including closed
locations, a prior family-home return, multiple branches and upgraded break
capacity. Reject incomplete-v3, unknown/custom location terms and impossible
legacy layouts before touching live state or destination files. Keep the
original input file intact and visibly explain any unsupported case.

Tests in `OfficeLifecycleTests.cs` and `OfficeSerializationTests.cs`:

- Ordinary move/branch/closure has no asset duplication, free resale or lost
  stock; unaffordable compound moves are fully atomic.
- Employer scope and monthly gross budget apply to furniture commands too.
- Both title-retention modes preserve old-business assets on a career change.
- Repeated returns home share one family furnishing set; old business-owned
  additions remain the old business's assets.
- Desk reservations for followers are revalidated at the actual transition.
- New saves round-trip, malformed state is rejected, supported imports keep
  balances/debt/rights/RNG intact, and unsupported files remain untouched.
- Full v4 command replay and replay after a converted checkpoint agree.

## 6. Add actual activity observations and appearance recipes

Instrument existing tick steps with a bounded `OfficeActivitySnapshot`, using
resolved outcomes rather than guessing from a planner queue. Preserve existing
step order and one-hour ownership: breaks, mentoring, conventions, promotion,
recovery, production, offsite travel and relocation must not appear as
simultaneous productive activities for the same person.

Add appearance recipes to people/candidates and a new-game protagonist editor
payload. Use a separate stable visual seed; do not call StaffRng/LocationRng
to choose hair or clothing. Validate component IDs and preserve the recipe
when a candidate becomes an employee or a creator changes business.

Tests in `OfficeActivityTests.cs`:

- A resolved break is not shown as the queued drawing task; travel/convention
  staff are not simultaneously seated in their office.
- A mentor/student hour has two correct people/anchors and no duplicate work.
- Midnight/career/closed-location snapshots have valid historical references.
- Appearance changes/rerolls and visual observation do not change gameplay
  IDs, RNGs, candidate talent or the results of advancing the same commands.
- Save/load restores stable appearance and the most recent activity snapshot.

## 7. Build the office scene, camera and reusable art

Create `godot/Office/OfficeView.tscn` with a 3D viewport/world, camera rig,
property renderer, furniture renderer and actor presenter. Add a thin
`DebugMain.Office.cs` integration without replacing the management harness.

Suggested responsibilities: `OfficeView.cs`, `OfficeCamera.cs`,
`OfficeSceneBuilder.cs`, `OfficeActor.cs`, `OfficePresenter.cs`, and small
reusable assets under `godot/Office/Assets/`. Logical layout data remains in
MangakaSim; meshes/art transforms are not the collision authority.

Build actual original furniture and a modular character kit, then add walk,
sit, draw and break loops. Create appearance-matched 2D portrait components,
small original wall graphics and manga work props. Record dimensions, pivots,
sources/licenses and creation method in `ASSETS.md`. Distinguish home, small
suite and larger commercial finishes rather than using one bare room at scale.

Implement camera pan/rotation/zoom/reset, room framing, cutaway walls and stable
selection. Use an activity-to-anchor mapping and clearance-valid walking paths.
The presenter reads snapshots; it never advances simulation or gates production
on animation completion. Catch-up and idle skip discard obsolete visual history.

Gate: a rendered family home and a full large studio have legible staff,
reachable desks, intentional art, usable camera controls and no pathing through
solid/private areas. All stages and offsite states have appropriate presentation.

## 8. Ambient occupants and timelapse in real rooms

Reuse the character kit for a separate ambient actor pool. Author family and
shared-commercial routines confined to their allowed areas. Reconstruct their
current placement from independent visual state and game time when switching
locations. Do not allocate staff IDs or consume facilities, payroll or tasks.

Integrate the proven timelapse approach with real meshes, hands, camera
rotation and wall cutaways. Accelerate animation/path time by the selected
speed; clear histories on discontinuities. Implement Off/Reduced/Full options
and keep current bodies/picking targets clear of ghost geometry.

Rendered checks:

- Family residents pass between shared anchors; neighbours use building halls
  without entering private studio space or becoming selectable employees.
- Pausing freezes actors and clears blur; resuming does not replay old trails.
- 2x/4x/8x movement visibly speeds up; ghosts are occluded by walls and never
  blur labels, the office shell or furniture.
- Camera rotation, zoom, selected people, a loaded save and a location switch
  do not leave phantom silhouettes or stale actors.
- A hidden office has no rendered actor/trail cost; its simulation continues.

## 9. Complete player-facing office controls

Implement location selector/alerts, click details, protagonist focus and quiet
attention markers. Connect details to existing staff/series controls, respecting
owner versus employed-lead permissions and former-business boundaries.

Implement the paused furniture editor: grid/rotation, drag validity reasons,
catalog/prices, inventory/storage, sell, desk assignment, locks, Auto-arrange,
optional package selection, combined move quote, Apply and Discard. Use clear
messages such as 'This chair blocks the doorway' or 'Two incoming staff need
desks'; do not expose internal grid/pathfinder terminology to players.

Use a pause owner/token so leaving the editor cannot dismiss a recap's pause
or start a game that was already paused. Disable background controls that
could mutate the quoted state. Handle stale async solver results and modal
close/load/new-game/location changes without applying a draft accidentally.

Gate: the user can play the whole furnish/hire/move/branch/career workflow from
actual controls, with correct money previews and no hidden debug-only steps.

## 10. Verify and report the actual delivered scope

Run focused tests during slices, then the full suite and warning-as-error build:

```powershell

dotnet build MangakaGame.sln --no-restore -warnaserror --verbosity quiet
```

Use the installed Godot .NET binary discovered from the environment/README.
Retain the existing entry points:

```powershell
& $godot --headless --editor --path godot --import --quit
& $godot --headless --path godot -- --smoke-test
& $godot --path godot -- --smoke-test --capture
```

Add `DebugMain.OfficeSmoke.cs` or a focused scene harness called by the existing
smoke runner. Place logs/captures under ignored `TestResults/`. Run rendered
automation hidden on Windows when a visible user walkthrough is not needed.
Headless checks cannot substantiate blur, art quality or renderer performance.

Required walkthrough scenarios:

| Scenario | Evidence required |
|---|---|
| Fresh family home | Two assigned-capable desks, zero rent, shared areas, ambient family and protagonist appearance |
| Editor transactions | Invalid access feedback, cancel purity, locks, Auto-arrange, price preview, apply and sale |

| Ordinary move | Owned assets move, family/landlord assets stay, surplus stored, existing downtime and stock constraints |
| Multiple locations | Hidden office progresses; alerts select correct site without transferring staff |
| Career change | Both rights modes, accepted followers, old business inventory retained, home return and employer limits |
| Time and activity | Breaks/mentoring/conventions, auto-pause, idle skip, all speeds and effect settings |
| Persistence | Fresh v4 round-trip/replay, supported v3 import, unchanged originals and clean rejection paths |
| Large shared office | 32 staff plus ambient occupants, readable cutaways, correct trail occlusion and bounded memory |

Capture stills at 1600×900 and 1280×720 for layout/UI inspection, and a short
moving sequence for timelapse. Measure a representative large-office run,
including 8x Full/Reduced effects, with hardware/settings and frame-time
distribution. The approximate 60-FPS target is not a result until measured.
Compare identical-command outcomes with office rendering shown, hidden and
disabled to establish that visual work does not alter the simulation.

Update README run/use guidance, the roadmap, and a Sub-project 4 delivery
record only after passing required checks. Record exact test counts, import
support boundaries, assets delivered, unresolved visual defects and performance
results. Leave unfinished checklist items open; do not call a prototype alone
the completed milestone. Commit/push only if requested separately.
